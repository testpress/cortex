## Context

When users tap on push notifications or follow web links generated by the Testpress LMS platform (such as `/dashboard`, `/courses/:id/contents/:id`, `/exams/chapter_content/:id`, `/p/:slug`, or `/products/:slug`), the incoming URLs reflect web endpoints. Cortex uses Flutter's `go_router` where navigation paths are organized differently:
- The dashboard is located at `/home`
- Lessons (video, PDF, notes) are located at `/study/lesson/:id`
- Products are located at `/store/product/:slug`
- Forum posts are located at `/home/discussions/forum/posts/:slug`

Currently, `PushNotificationService._handleDeepLink(String? url)` in `packages/testpress` passes the raw path directly into `router.push(path)`. When a path like `/dashboard` or `/exams/chapter_content/2054/?content_detail_v2=true` is received, `go_router` throws:
```text
GoException: no routes for location: /dashboard
```
resulting in a "Page Not Found" screen.

The native Android app (`in.testpress.testpress.ui.utils.DeeplinkHandler`) solved this by parsing path segments and dispatching the user to the corresponding Activity. Cortex requires an equivalent deep link resolution component.

## Goals / Non-Goals

**Goals:**
- Provide a platform-agnostic, deterministic `DeepLinkHandler.resolve(String? url)` utility in `packages/testpress`.
- Parse both absolute URLs (`https://...`) and relative URI paths, stripping query parameters and trailing slashes.
- Accurately map legacy Testpress notification and web URL patterns to internal Cortex `go_router` paths.
- Safely fall back to `/home` for unknown or malformed paths, preventing unhandled navigation errors.
- Integrate `DeepLinkHandler` with `PushNotificationService._handleDeepLink`.
- Provide 100% unit test coverage for all URL patterns and edge cases.

**Non-Goals:**
- Modifying OS-level native intent filters or Associated Domains configs in `AndroidManifest.xml` / `Info.plist` (existing configurations remain untouched).
- Changing backend notification generation or API payload contracts.
- Persisting state across authentication handoffs if unauthenticated (auth guards already manage route access).

## Decisions

### Decision 1: Pure Stateless Utility vs Stateful Service
- **Choice**: Implement `DeepLinkHandler` as a pure, stateless class with a static method `resolve(String? rawUrl) -> String`.
- **Rationale**: URL parsing and pattern matching are deterministic functions without internal state or asynchronous dependencies. A static pure function is simple, easy to test, fast to execute, and easily callable from any notification or link listener.

### Decision 2: Sanitization and Segment-Based Matching
- **Choice**:
  1. Trim whitespace; return `/home` if null or empty.
  2. Parse with `Uri.tryParse()`. If parsing fails, return `/home`.
  3. Extract `pathSegments` (filtering out empty tokens) and discard query parameters / hash fragments.
  4. Match based on path segments and slugs/IDs.
- **Rationale**: Web URLs sent via notifications frequently include analytics or HTMX query parameters (e.g. `?content_detail_v2=true&use_htmx_for_partial_views=true`). Stripping query parameters before matching prevents routing errors.

### Decision 3: URL Route Mapping Table

| Incoming Pattern | Path Segments | Resolved Cortex Route |
| :--- | :--- | :--- |
| Empty / Malformed | `[]` | `/home` |
| `/dashboard`, `/learn`, `/leaderboard` | `['dashboard']`, `['learn']`, etc. | `/home` |
| `/login` | `['login']` | `/login` |
| `/activate`, `/register` | `['activate']`, `['register']` | `/signup` |
| `/exams/chapter_content/:id` | `['exams', 'chapter_content', id]` | `/study/lesson/:id` |
| `/courses/:courseId/contents/:id` | `['courses', courseId, 'contents', id]` | `/study/lesson/:id` |
| `/chapters/:chapterId/:id` | `['chapters', chapterId, id]` | `/study/lesson/:id` |
| `/courses` | `['courses']` | `/study` |
| `/products/:slug` | `['products', slug]` | `/store/product/:slug` |
| `/store/product/:slug` | `['store', 'product', slug]` | `/store/product/:slug` |
| `/products`, `/store` | `['products']`, `['store']` | `/store` |
| `/p/:slug`, `/posts/:slug` | `['p', slug]`, `['posts', slug]` | `/home/discussions/forum/posts/:slug` |
| `/exams`, `/exams/available`, etc. | `['exams', ...]` | `/exams` |
| Unrecognized / Unknown | Any other segment sequence | `/home` (safe fallback) |

### Decision 4: Fallback Behavior
- **Choice**: When a deep link cannot be matched to a known destination, return `/home`.
- **Rationale**: Crashing with `GoException` or showing a broken 404 screen when tapping a notification is a jarring experience. Falling back to the home screen ensures the app opens cleanly and remains interactive.

## Risks / Trade-offs

- **[Risk] Deep link requiring authentication**: If an unauthenticated user opens a lesson deep link, the user must be redirected to login.
  - *Mitigation*: GoRouter's existing auth redirects in `AppRouter` or the route guards automatically protect `/study/*` routes, redirecting unauthenticated users to `/login`.
- **[Trade-off] Content ID routing vs Course hierarchy**: Incoming content URLs (`/exams/chapter_content/:id`) do not specify the parent course ID.
  - *Mitigation*: Cortex's `LessonDetailOrchestrator` (`/study/lesson/:id`) fetches content details and parent hierarchy directly by content ID, rendering video, PDF, or notes seamlessly.
